摘要

MCP（Model Context Protocol，模型上下文协议）是一种开放协议，用于标准化 AI 模型与外部数据源、工具之间的通信方式。它由 Anthropic 于 2024 年 11 月提出并开源，目标是解决 AI 应用开发中"每个模型对接每个工具都需要定制集成"的碎片化问题。MCP 采用客户端-服务器架构，通过 JSON-RPC 2.0 进行消息传递，支持资源（Resources）、工具（Tools）和提示词（Prompts）三类原语。

学习目标

  • 用自己的话解释 MCP 解决的核心问题（"AI 集成的 USB-C 接口"）
  • 区分 MCP 中的 Host、Client、Server 三个角色及其职责
  • 描述 MCP 的三类原语（Resources / Tools / Prompts）及其适用场景
  • 理解 MCP 的传输层选项（stdio 与 Streamable HTTP）及各自适用场景
  • 独立搭建一个最小 MCP Server，并从一个 MCP Client 调用其工具
  • 识别 MCP 当前的安全边界与已知开放问题

核心概念

为什么需要 MCP

在 MCP 出现之前，AI 应用对接外部系统通常需要为每个"模型-工具"组合编写定制胶水代码，导致集成成本高、上下文管理混乱、安全边界模糊。MCP 标准化了这一层，让工具提供方只需实现一次 MCP Server，即可被任何支持 MCP 的客户端复用。

三个核心角色

角色说明典型例子
Host用户交互的应用程序，负责管理多个 Client 连接Claude Desktop、IDE 插件
Client与 Server 建立 1:1 连接的组件Host 内部的连接器
Server暴露资源/工具/提示词的进程文件系统服务器、数据库服务器

三类原语

  • Resources（资源）：可读取的数据实体，如文件内容、数据库记录。
  • Tools（工具）：可执行的函数，模型可以主动调用。
  • Prompts（提示词）：可复用的提示模板。

技术架构

┌─────────────────────────────────────┐
│            Host (应用层)              │
├─────────────────────────────────────┤
│            MCP Client                │
├─────────────────────────────────────┤
│   JSON-RPC 2.0 消息层                │
├──────────────┬──────────────────────┤
│  stdio       │  Streamable HTTP      │
│  (本地进程)  │  (远程服务)            │
└──────────────┴──────────────────────┘

生命周期：初始化 → 就绪 → 运行 → 关闭。

传输层对比：stdio 适合本地、安全敏感场景；Streamable HTTP 适合跨网络、多租户场景。

实践步骤

  1. 环境准备：Node.js 18+ 或 Python 3.10+，安装 MCP SDK
  2. 实现最小 MCP Server，注册一个工具（如 add）
  3. 运行 Server（stdio 传输）
  4. 用 Client 调用工具，验证结果
  5. （可选）接入 Claude Desktop

风险与开放问题

已知风险

  • 工具滥用
  • 提示注入
  • 传输安全
  • 版本兼容

开放问题

  • 与 OpenAI Function Calling、Google A2A 的竞争/融合
  • 标准化组织归属
  • 大规模生产环境性能基准
  • 多 Server 上下文窗口管理
