向量数据库核心原理

学习报告 · 2026-07-31

摘要

向量数据库专门用于存储、索引和检索高维向量数据，解决语义相似性搜索问题。通过嵌入模型将非结构化数据转化为向量，利用近似最近邻（ANN）算法快速找到相似条目。

学习目标

  • 理解向量数据库与传统关系型数据库的差异
  • 掌握三种相似度度量及其适用场景
  • 了解 HNSW、IVF、PQ 索引的构建与权衡
  • 熟悉典型系统架构与查询链路
  • 完成最小可行实践：文本到向量检索
  • 识别当前挑战与开放问题

核心概念

向量（Embedding）

将非结构化数据映射为固定维度浮点数数组，语义相近的数据在向量空间中距离相近。

相似度度量

度量方式公式（示意）适用场景
余弦相似度cos(θ) = (A·B) / (‖A‖·‖B‖)文本语义相似度
欧氏距离（L2）d = √(Σ(ai - bi)²)图像特征
内积（点积）A·B = Σ(ai·bi)推荐系统

最近邻搜索（NN）与近似最近邻（ANN）

精确 KNN 暴力扫描，时间复杂度 O(n·d)；ANN 牺牲少量精度换取速度提升。

召回率（Recall）

衡量 ANN 检索质量：召回率 = 检索到的真实最近邻数 / 理论最近邻总数。

技术架构

应用层：SDK / API（写入向量、查询向量）
查询层：相似度计算、Top-K 排序、过滤条件
索引层：HNSW / IVF / PQ / 混合索引
存储层：向量数据 + 元数据（标量）持久化
基础设施：分布式节点、复制、故障恢复

写入链路：客户端传入数据 → 写入日志（WAL）→ 构建/更新索引 → 元数据存储。

查询链路：查询向量 → 粗粒度过滤 → ANN 索引候选集 → 精确计算排序 → 后处理。

三大主流索引机制

HNSW

多层图结构，查询延迟低、召回率高，无需训练，但内存占用大。

IVF

聚类分桶，内存效率高，适合超大规模数据，需训练。

PQ

子空间量化，极低内存占用，适合十亿级场景，有信息损失。

索引查询速度内存占用召回率是否需要训练典型规模
HNSW快高高否百万~千万
IVF中中中是千万~亿
IVF-PQ中快低中低是亿级以上

实践步骤

  1. 准备嵌入模型（如 all-MiniLM-L6-v2）
  2. 选择向量数据库（如 Qdrant、Milvus）
  3. 创建集合并配置向量大小与距离度量
  4. 将文档切块并生成向量，写入数据
  5. 执行相似性查询，获取 Top-K 结果
  6. 评估召回率并调优参数（如 M、ef_search）

风险与开放问题

技术风险

  • 数据更新成本高
  • 内存瓶颈
  • 维度灾难

开放问题

  • 混合查询（Hybrid Search）
  • 动态索引
  • 可解释性
  • 评估基准不统一
  • 多模态统一向量空间
